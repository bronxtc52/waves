# wave-autobot

> **⚠ Волна работает в auto-режиме прав.** Диспетчер запускает каждую волну командой
> `claude --permission-mode auto`: агент сам правит файлы, гоняет команды, коммитит и пушит, не
> спрашивая подтверждения на каждое действие. Поэтому:
> - запускайте волны **только в своём репозитории** и на машине, где вы готовы к такому агенту;
> - волна работает **только в своей feature-ветке** `wab/<chain>/<run_id>/<волна>` (отдельный
>   `git worktree`) и открывает PR — в базовую ветку она сама не пишет;
> - **`automerge` по умолчанию выключен**: PR мерджит человек, диспетчер только ждёт мерджа.
>   Включайте `automerge: true`, только если CI репозитория действительно проверяет изменения.

Скилл для Claude Code: большая задача режется на **волны**, каждая волна — свежая сессия Claude в
tmux и один PR. Диспетчер ведёт волны по очереди: следит за заполнением контекста (контрольная
точка → `/clear` → продолжение по handoff), за вопросами `BLOCKED`, проверяет гейт мерджа по фактам
GitHub и после мерджа сам запускает следующую волну. Дашборд показывает ход цепочки.

Подробно о скилле для самого Claude — [SKILL.md](SKILL.md); протокол сессии волны —
[PROTOCOL.md](PROTOCOL.md); журнал изменений — [CHANGELOG.md](CHANGELOG.md).

## Как это устроено

1. **Фаза A — план.** Вы вместе с архитектором (сессия Claude на модели `roles.architect`) пишете
   короткое ТЗ и план `waves.md`: у каждой волны цель, «Готово, когда», команда проверки и
   зависимости. Одобренный план фиксируется в `waves.json` его хешем `plan_sha256`.
2. **Фаза B — волны.** `wab.py launch` запускает волну W1: `git worktree` от свежего
   `origin/<base_branch>`, tmux-сессия `wab-<chain>-<волна>` с Claude на модели кодера.
   `wab.py watch` ведёт цепочку дальше:
   - контекст выше `ctx_limit` → сообщение `WAB-CHECKPOINT` → волна пишет `handoff.md` и
     `HANDOFF_READY` → `/clear` → продолжение по handoff со свежим контекстом;
   - `BLOCKED: <вопрос>` в файле статуса → событие в журнале; вы отвечаете прямо в окне волны;
   - `DONE` → **гейт мерджа**: PR ветки волны найден, HEAD волны = HEAD PR, рабочая копия чистая,
     все check-runs строго `success`, план не менялся. Отказ — `BLOCKED: merge gate: <причина>`, и
     причина уходит в окно волны (волна исправляет и снова пишет `DONE`);
   - гейт пройден → ждём мерджа человеком (или, при `automerge: true`, один
     `gh pr merge --squash --match-head-commit <sha>`) → проверка, что merge-коммит есть в
     `origin/<base_branch>` → окно волны закрывается → следующая волна стартует сама по
     `next-prompt.md`, который написала предыдущая;
   - после последней волны — итог `runs/<run_id>/chain-result.md`.

## Роли и модели

Каждая роль работает на своей модели. Кодер — основная сессия волны; тестер, ревьюер и читатель —
её субагенты (передаются флагом `claude --agents` только в эту сессию, `~/.claude/agents` не
трогается).

| Роль | Кто это | Модель по умолчанию |
|---|---|---|
| `architect` | фаза A: ТЗ и план вместе с человеком | `fable` |
| `coder` | основная сессия волны: красный тест, код, PR | `opus` |
| `tester` | субагент `wave-tester`: свежий контекст, PASS/FAIL, код не меняет | `sonnet` |
| `reviewer` | субагент `wave-reviewer`: дифф против цели, находки P1/P2 | `fable` |
| `reader` | субагент `wave-reader`: читает большие файлы, отвечает коротко | `haiku` |

Перед запуском диспетчер проверяет доступность моделей коротким `claude -p`. Недоступная модель
заменяется на `fallback_model` (по умолчанию `opus`) с событием в журнале и пометкой в дашборде; если
недоступен и fallback — запуск отказывает. Проверить заранее: `wab.py models waves.json`.

## Установка

Нужны: [Claude Code](https://docs.claude.com/en/docs/claude-code/setup) (`claude`), `tmux` ≥ 3.2,
`gh` (GitHub CLI, авторизованный: `gh auth login`), `git` ≥ 2.36, `python3` ≥ 3.10 и модуль `rich`
(только для дашборда). Linux или macOS.

```sh
git clone https://github.com/bronxtc52/waves.git ~/src/waves && cd ~/src/waves && ./install.sh
```

`install.sh` проверяет зависимости (все нехватки печатает разом, с подсказкой, как поставить) и
ставит симлинк `~/.claude/skills/wave-autobot` на каталог клона. Повторный запуск безопасен; симлинк
в другое место заменяется с сообщением; если на этом месте лежит обычный каталог или файл, скрипт
ничего не трогает и завершается ошибкой. Обновление — `git pull` в клоне.

**Клавиша Ctrl+\\** — открыть/закрыть окно текущей волны всплывающим окном поверх дашборда. Добавьте
в `~/.tmux.conf` (путь печатает `install.sh`) и перечитайте конфиг:

```
source-file "/путь/к/клону/keys.tmux"
```

и укажите tmux, какую цепочку открывать (кавычки обязательны, если в пути есть пробелы):

```sh
tmux set -g @wab_open "$HOME/.claude/skills/wave-autobot/scripts/wab-open /путь/к/репозиторию/waves.json"
```

## Быстрый старт за 5 шагов

Пример — игрушечная цепочка из двух волн в [`examples/`](examples/): W1 добавляет `hello.py` с
тестом, W2 — флаг `--name`. Все команды ниже берут скрипты из каталога скилла:

```sh
WAB="$HOME/.claude/skills/wave-autobot"
```

**1. Скопируйте пример в свой репозиторий** (корень его рабочей копии, ветка `main`):

```sh
cd /путь/к/вашему/репозиторию
cp "$WAB"/examples/waves.md "$WAB"/examples/waves.json "$WAB"/examples/prompt-W1.md .
echo 'runs/' >> .gitignore
```

В `runs/<run_id>/` рядом с `waves.json` диспетчер держит состояние, журнал событий и рабочие копии
волн — в git им не место.

**2. Поправьте `waves.json`:** `repo` — ваш `owner/name` на GitHub, `checkout` — абсолютный путь к
корню рабочей копии (вывод `pwd`), `run_id` — имя прогона (например, сегодняшняя дата). Если
меняли `waves.md` — пересчитайте `plan_sha256` (без этого `launch` откажет: `BLOCKED: plan changed
since approval`):

```sh
python3 -c 'import hashlib, json; c = json.load(open("waves.json")); c["plan_sha256"] = hashlib.sha256(open("waves.md", "rb").read()).hexdigest(); json.dump(c, open("waves.json", "w"), ensure_ascii=False, indent=2)'
```

(или `sha256sum waves.md` / на macOS `shasum -a 256 waves.md` и вписать хеш руками).

**3. Проверьте конфиг и модели:**

```sh
python3 "$WAB"/scripts/wab.py validate waves.json
python3 "$WAB"/scripts/wab.py models waves.json
```

**4. Запустите первую волну и диспетчер** — внутри tmux, например в сессии `wab`:

```sh
tmux new -s wab
python3 "$WAB"/scripts/wab.py launch waves.json W1 prompt-W1.md
python3 "$WAB"/scripts/wab.py watch waves.json
```

**5. Откройте дашборд** в соседнем окне tmux (`Ctrl-b c`) и следите:

```sh
python3 "$WAB"/scripts/dash.py waves.json
```

Волна написала `BLOCKED` — подключитесь к её окну (`tmux attach -t =wab-hello-w1`, выйти — `Ctrl-b d`,
или `Ctrl+\`) и ответьте текстом. Дашборд показал «ждёт мерджа PR #N» — посмотрите PR и смержите
его; диспетчер сам запустит W2. Итог цепочки — `runs/<run_id>/chain-result.md`.

Для своей задачи план пишется в фазе A с архитектором — см. [SKILL.md](SKILL.md).

## `waves.json` — поля (схема v1)

Лишние ключи и дубликаты ключей — ошибка. Проверка: `wab.py validate waves.json`.

| Поле | Обязательно | По умолчанию | Смысл |
|---|---|---|---|
| `chain` | да | — | Имя цепочки: `[A-Za-z0-9_-]`, без точек. Входит в имя ветки и tmux-сессии `wab-<chain>-<волна>`. |
| `run_id` | да | — | Имя прогона: `[A-Za-z0-9._-]`, годное для ветки git. Состояние — в `runs/<run_id>/` рядом с `waves.json`. |
| `repo` | да | — | Репозиторий на GitHub, `owner/name`: по нему гейт ищет PR и check-runs. |
| `checkout` | да | — | Абсолютный путь к корню рабочей копии этого репозитория; от неё создаются `git worktree` волн. |
| `waves` | да | — | Непустой список волн (поля ниже), в порядке выполнения. |
| `base_branch` | нет | `main` | Базовая ветка: от свежего `origin/<base_branch>` стартует волна, в неё идёт PR. |
| `automerge` | нет | `false` | `true` — диспетчер сам делает `gh pr merge --squash --match-head-commit` после гейта. Требует `plan_sha256`. |
| `plan_sha256` | нет | `null` | sha256 одобренного `waves.md` (64 строчные hex-цифры). Сверяется при запуске и на каждом такте гейта. Без него нет автозапуска следующей волны и нельзя `automerge`. |
| `roles` | нет | см. «Роли и модели» | Объект `{роль: модель}`, только ключи `architect`, `coder`, `tester`, `reviewer`, `reader`; пропущенные берут умолчания. |
| `fallback_model` | нет | `opus` | Замена для недоступной модели роли. |
| `ctx_limit` | нет | `300000` | Порог контекста (токены) для запроса контрольной точки. Меняется на ходу без перезапуска `watch`. |
| `idle_minutes` | нет | `12` | Экран волны не меняется столько минут — событие «idle». Меняется на ходу. |
| `tick_seconds` | нет | `60` | Период такта диспетчера, секунды. Меняется на ходу. |

Поля волны:

| Поле | Обязательно | Смысл |
|---|---|---|
| `id` | да | `[A-Za-z0-9_-]`, уникальный без учёта регистра (`W1`, `W2`, …). |
| `title` | да | Короткое название. |
| `goal` | да | Цель волны одной-двумя фразами. |
| `done_when` | да | Непустой список проверяемых критериев «Готово, когда», без повторов. |
| `check` | да | Команда, которая доказывает готовность. |
| `depends_on` | нет (`[]`) | id волн, от которых зависит эта; только объявленные выше. |

На ходу `watch` перечитывает только три порога (`ctx_limit`, `idle_minutes`, `tick_seconds`); смена
остальных полей применяется перезапуском `watch` (он предупредит событием).

## Команды

Все — `python3 "$WAB"/scripts/<скрипт> …`.

| Команда | Что делает |
|---|---|
| `wab.py validate <waves.json>` | Проверить конфиг и напечатать его с умолчаниями. |
| `wab.py models <waves.json> [--refresh]` | Роли → модели с проверкой доступности и fallback; `--refresh` проверяет заново. |
| `wab.py launch <waves.json> <волна> <файл-промпта>` | Запустить одну волну в tmux (одна текущая волна на прогон). |
| `wab.py watch <waves.json>` | Вести цепочку: контрольные точки, `BLOCKED`, гейт, мердж, следующая волна. Один `watch` на прогон. Перезапуск безопасен: состояние — в `runs/<run_id>/state.json`. |
| `wab.py status <waves.json>` | Статус волн одним экраном. |
| `dash.py <waves.json>` | Живой дашборд (внутри tmux; выход — `Ctrl-C`): волны, контекст, события, роли и fallback, фаза гейта; ставит короткую строку в `status-right` своей сессии tmux. |
| `wab-open <waves.json>` | Открыть окно текущей волны (его вызывает `Ctrl+\` из `keys.tmux`). |

## Ограничения

- **Вычистка секретов — best-effort.** Всё, что из окна волны попадает в события и дашборд,
  проходит `redact`: шаблоны скрывают известные формы ключей, токенов, паролей, userinfo в URL и
  адресов почты, но полноту не гарантируют. Не выводите секреты в окно волны; полный текст остаётся в
  каталоге волны `runs/<run_id>/<волна>/`.
- **Без `plan_sha256` нет автозапуска** следующей волны (диспетчер печатает команду `launch`) и нельзя
  включить `automerge`.
- **Одна волна за раз** в прогоне и один `watch` на прогон; волны идут строго по порядку `waves`.
- **Гейт требует CI:** без check-runs на HEAD PR гейт ждёт («нет check-runs»), а любой итог, кроме
  `success` (в том числе `neutral` и `skipped`), — отказ.
- PR ищется только из ветки волны в самом `repo`, PR из форков не учитываются; автомердж — только squash.
- Нужны tmux ≥ 3.2, git ≥ 2.36, авторизованный `gh`, Python ≥ 3.10; Linux или macOS.
- Контекст волны меряется по журналам Claude Code в `~/.claude/projects/`: при смене их формата
  контрольные точки могут перестать запрашиваться.
- Известные пробелы: таймаут `gh pr merge` даёт `BLOCKED` без проверки, не смержен ли PR уже; ручной
  повторный `launch` волны забывает отметку о её мердже.
