# Журнал изменений

## Не выпущено

### Добавлено
- W3: сессия волны запускается с `--session-id`, первое сообщение и продолжение после `/clear` начинаются с метки `[wab:<цепочка>/<прогон>/<волна>]`; новый журнал после `/clear` привязывается по метке.
- W3: `TranscriptCache` — инкрементальное чтение журнала сессии (хвост 4 МБ при первом чтении, неполная строка, сброс при усечении, подмене и переписывании начала).
- W3: проверка tmux не старше 3.2 в `launch` и `watch` с понятным сообщением вместо traceback.
- W3: пин плана — `launch` сверяет sha256 `waves.md` с `plan_sha256` (`BLOCKED: plan changed since approval`); без `plan_sha256` — предупреждение в stderr.
- W3: `dispatcher.lock` — второй `watch` на тот же прогон не стартует.
- W3: срок ожидания новой сессии `AWAIT_SESSION_MINUTES` (10 мин): не найдена по метке — одно событие «контекст не меряется, контрольная точка не запрашивается», поиск продолжается.
- W3: тесты redact по классам пропусков (`tests/fixtures/redact_classes.json`), контрольные обычные фразы и время на 300 КБ входа.
- W3: тесты на перенесённое из прототипа поведение: `wait_ready` по сроку, неготовое окно при `launch`, DONE и мёртвая сессия, дедупликация BLOCKED, перезапуск `watch` в фазах running и checkpoint, многострочное событие, дашборд при гонке чтения.
- W3: `redact` явно описан как best-effort (README, SKILL): шаблоны скрывают известные формы, полноту не гарантируют.

### Исправлено
- W3: отправленный промпт не даёт совета убить сессию: флаг `prompt_maybe_sent` сохраняется до `send_text`, и ни `tick`, ни повторный `launch` (фазы sending, not_ready) не советуют `tmux kill-session`, только открыть окно и при необходимости отправить `first-prompt.md`; совет kill остался для `starting` без отправки. Ветка sending→not_ready больше не затирает status, записанный агентом: не STARTING — задача дошла, волна идёт (`running`).
- W3: у записи без `sessions` ожидание новой сессии (`await_session`) приоритетнее миграции: журнал после /clear привязывается только по метке со снятием флага, иначе миграция забирала его, и контрольные точки переставали запрашиваться.
- W3: launch, убитый после отправки первого промпта, оставлял запись `starting`, и watch советовал `tmux kill-session` (потеря работы агента); теперь launch сохраняет фазу `sending` перед отправкой, а watch при мёртвом launcher смотрит журнал `sessions[0]`: метка волны есть — волна идёт (`running`), нет — `BLOCKED` без совета закрывать окно, с текстом из `first-prompt.md`. `starting` (задача точно не отправлена) работает как раньше.
- W3: запись волны, созданная до W3 (есть cwd, нет `sessions`), давала контекст 0 на каждом такте, и контрольная точка не запрашивалась; теперь первый такт привязывает самый свежий журнал каталога, которым не владеет ни одна волна, и сохраняет `sessions` (без журналов — одно событие «контекст не меряется: нет журнала», попытки продолжаются).
- W3: `launch` проверял `waves.md` до проб моделей, и правка плана за минуты проб не замечалась; проверка плана повторяется под блокировкой прогона перед записью резерва.
- W3: `redact` пропускал хвост пароля, когда в значении JSON внутри строки перед кавычкой стояло нечётное число слешей больше одного (`\\\"`); закрывающая кавычка теперь ровно разделитель своего уровня экранирования (уровни 0, 1, 2).
- W3: контекст измерялся по «самому свежему файлу каталога» и мог принадлежать чужой сессии; теперь только по журналу `sessions[-1]` волны (дашборд считает журналы волны, а не каталога).
- W3: после `/clear` контрольная точка могла запрашиваться сразу по старому журналу с большим контекстом; пока новая сессия не привязана, контекст не меряется и контрольная точка не запрашивается.
- W3: ветка HANDOFF_READY держала блокировку прогона до ~96 с (`/clear`, сон, `wait_ready`) и не сохраняла состояние до действия; теперь машина фаз по тикам (clearing, resuming, running), каждая фаза сохраняется до действия, в тике нет долгих ожиданий.
- W3: перезапущенный `watch` в фазе `clearing` мог послать `/clear` повторно или не послать вовсе; в фазе `resuming` продолжение вслепую не досылается (BLOCKED с просьбой проверить окно).
- W3: окончание `/clear` определялось только паузой; теперь по признаку готовности окна и диалогу доверия без цикла в тике.
- W3: `launch`, убитый после `tmux new-session`, оставлял фазу `starting`; теперь при живом окне BLOCKED с указанием, что сделать (kill-session и повторный `launch`), без окна — dead.
- W3: падение `tmux new-session` давало traceback и оставляло резерв; теперь резерв снимается, ошибка tmux показана текстом.
- W3: правка `waves.md` после одобрения не замечалась (`plan_sha256` не использовался).
- W3: два `watch` на один прогон могли вести волну одновременно.
- W3: не-UTF-8 локаль и невалидные байты в выводе tmux роняли CLI, `event` и чтение файлов; везде явная кодировка UTF-8, tmux с `-u`.
- W3: redact не скрывал JSON внутри строки (`{\"password\": \"x\"}`), экранированную кавычку в значении (`"pa\"ss"`), имена `SECRET_KEY`, `AWS_SECRET_ACCESS_KEY`, `private_key`, `passphrase`, `password_hash`, PHP `'password' => 'x'`, флаг `--password x`.
- W3: шаблон адреса почты в redact был квадратичен (300 КБ без «@» — около 115 с под блокировкой прогона); теперь линейный (меньше 1 с).
- W3: при повторном `launch` волны журналы прошлых попыток с той же меткой могли привязаться как «новая сессия»; прежние `sessions` уходят в `attempts`.
- W3: ожидание новой сессии не имело срока: при ненайденной метке контекст молча не мерился бесконечно; теперь событие через `AWAIT_SESSION_MINUTES`.
- W3: после восстановления (`resuming`/`clearing` → `not_ready` → ручное `RUNNING`) волна снова мерила старый журнал выше порога и сразу запрашивала контрольную точку; теперь флаг ожидания новой сессии ставится и сохраняется до `/clear` и снимается только привязкой новой сессии по метке.
- W3: текст продолжения после `/clear` (с меткой волны) пишется в `continue-prompt.md` каталога волны до отправки `/clear`; сообщения BLOCKED (resuming, окно не готово после `/clear`) и событие о ненайденной за `AWAIT_SESSION_MINUTES` сессии называют файл и метку: при ручном продолжении без метки новая сессия не привяжется.
- W3: `TranscriptCache` после сброса по несовпадению начала читал хеш середины файла, и повторное переписывание на месте без смены размера не замечалось; теперь чтение начала всегда с нуля.
- W3: FIFO на месте `waves.md` вешал `launch` в `open()`; теперь открытие неблокирующее, не обычный файл — `BLOCKED: plan changed since approval`.
