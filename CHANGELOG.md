### Исправлено
- W4: `probe_model` падал с `UnicodeEncodeError`/`UnicodeDecodeError` в не-UTF-8 локали (`LC_ALL=C` без UTF-8 mode); вывод `claude` читается как UTF-8 с заменой, промпт в argv кодируется явно.
- W4: `RESUMING` писался в `status` после отправки продолжения и затирал `RUNNING`/`BLOCKED`/`DONE`, который быстрый агент уже успел записать; теперь пишется до отправки, после неё статус не трогается.
- W4: `Ctrl+\` внутри попапа волны (клиент `ignore-size`) открывал ещё один попап вместо закрытия; клиент `ignore-size` теперь проверяется первым (`detach-client`).
- W3: запись до W3 в фазе `starting` (без ключа `sessions`) — доставка первого промпта неоднозначна: `tick` даёт BLOCKED без совета `tmux kill-session` (или `running`, если агент уже писал статус), `launch` при живой сессии тоже не советует её убивать.
- W3: неоднозначная отправка `/clear` не повторяется вслепую: перед вводом сохраняется `clear_sent="sending"`, и перезапущенный `watch` при таком значении даёт BLOCKED с просьбой очистить поле и отправить `/clear` вручную вместо повторного ввода («/clear/clear»).
- W3: привязка нового журнала только по метке в начале первого настоящего сообщения (или в начале `<command-args>` при продолжении slash-командой): журнал, лишь цитирующий метку, больше не привязывается.
- W3: перезапуск `watch` в фазе `resuming`, когда продолжение уже доставлено (в журнале после `pre_clear` есть метка), привязывает сессию и ставит `running` без BLOCKED; статус агента не затирается. Нет журнала — BLOCKED как раньше.
- W3: журнал, существовавший до /clear, не принимается за новую сессию: при переходе checkpoint→clearing в записи волны сохраняется снимок `pre_clear` (журналы каталога до /clear), `find_new_session` пропускает их, привязка снимает снимок; непривязанный журнал прошлой попытки с той же меткой больше не снимает ожидание. Записи без `pre_clear` ведут себя как раньше.
- W3: кэш журнала расширяет проверяемое начало по мере роста файла: пустой или короткий первый снимок префикса больше не слепит проверку, переписывание на том же inode с тем же размером обнаруживается, чтение остаётся инкрементальным.
- W3: тест `test_checks_under_lock` не зависит от скорости машины: останов на второй проверке launch (под резервом), а не на первой, где блокировка отпускалась и W2 на медленном CI мог выиграть резерв (код 4 у W1).
- W3: отправленный промпт не даёт совета убить сессию: флаг `prompt_maybe_sent` сохраняется до `send_text`, и ни `tick`, ни повторный `launch` (фазы sending, not_ready) не советуют `tmux kill-session`, только открыть окно и при необходимости отправить `first-prompt.md`; совет kill остался для `starting` без отправки. Ветка sending→not_ready больше не затирает status, записанный агентом: не STARTING — задача дошла, волна идёт (`running`).
- W3: у записи без `sessions` ожидание новой сессии (`await_session`) приоритетнее миграции: журнал после /clear привязывается только по метке со снятием флага, иначе миграция забирала его, и контрольные точки переставали запрашиваться.

### Известные ограничения
- Сквозной офлайн-тест (`tests/test_e2e_offline.py`) после события «новая сессия привязана по метке» сразу читает `state.json`, а диспетчер пишет событие до `save_state()`: в редком окне между ними тест может упасть при верной работе диспетчера (на CI и под нагрузкой не воспроизводилось).
- Изоляции волны нет: `git worktree` и feature-ветка — порядок работы, а не ограничение прав; базовую ветку защищает только защита ветки на GitHub (см. README).
- Прочие ограничения — README, раздел «Ограничения».
