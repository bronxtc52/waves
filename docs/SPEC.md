# ТЗ: скилл `wave-autobot` (публичная упрощённая версия)

Согласовано владельцем 2026-10-02. Репозиторий: `bronxtc52/waves` (публичный, MIT, всё на русском).

## Проблема

Наш режим `/superarmanda --waves` неотделим от superarmanda и приватной инфраструктуры
(Key Vault, `cc-autonomy`, Codex-ревьюер, manifest) — передать его другим людям нельзя.
Прототип wave-autobot (`agent-config/docs/specs/2026-09-30-superarmanda-waves/prototype/`)
прост, но без дисциплины качества и с известными граблями. Нужен самостоятельный скилл,
который человек ставит одной командой и ведёт большую задачу волнами.

## Что делаем

1. Репозиторий: `SKILL.md`, `PROTOCOL.md`, `scripts/wab.py` (диспетчер), `scripts/dash.py`
   (дашборд на `rich`), `scripts/wab-open`, `keys.tmux`, `install.sh` (симлинк в
   `~/.claude/skills/wave-autobot`, проверка зависимостей), `README.md` (быстрый старт +
   предупреждение про auto-режим), `examples/` (`waves.json`, `waves.md`), `docs/SPEC.md`.
2. **Фаза A — сессия архитектора (Fable).** Короткое ТЗ → план `waves.md` (у каждой волны:
   цель, «Готово, когда…», команда проверки, зависимости) → одобрение человеком →
   `waves.json` с хешем одобренного `waves.md` → запуск диспетчера.
3. **Фаза B — диспетчер** ведёт волны по порядку: волна стартует в `git worktree` от свежего
   `origin/<база>` → tmux-сессия `claude --model <coder> --permission-mode auto
   --append-system-prompt-file PROTOCOL.md --agents <json ролей>`.
4. **Протокол волны** (сценарий кодера): красный тест → реализация → субагент `wave-tester`
   (свежий контекст, PASS/FAIL) → субагент `wave-reviewer` (сверка диффа с планом, ≤2 кругов,
   P1 → обратно кодеру) → PR → `DONE`. Вопрос человеку — строка `BLOCKED: …` в файле
   `status`, а не `AskUserQuestion`.
5. **Контрольная точка по контексту:** порог в `waves.json` → `HANDOFF_READY` → `/clear` →
   продолжение по `handoff.md`; протокол переживает `/clear`.
6. **Роли по моделям** в `waves.json → roles`, по умолчанию
   `architect: fable, coder: opus, tester: sonnet, reviewer: fable, reader: haiku`.
   Субагенты задаются на сессию волны флагом `claude --agents` (глобальный
   `~/.claude/agents` не трогается). Модель недоступна на тарифе → роль переходит на
   `fallback_model` (по умолчанию `opus`) с предупреждением в дашборде и журнале.
7. **Гейт перед следующей волной** — только факты GitHub: PR ветки волны найден; все
   check-runs на текущем `headRefOid` `completed` + `success` (и их ≥1); хеш `waves.md`
   совпадает с одобренным — проверяется и перед мерджем, и перед запуском следующей волны. Иначе цепочка стоит, дашборд показывает причину.
8. **Мердж:** по умолчанию автомерджа нет — волна сдаёт PR, человек мерджит, диспетчер ждёт
   `MERGED`. Флаг `"automerge": true` → `gh pr merge --squash --match-head-commit <sha>` при
   зелёном гейте.
9. **Уведомления — только дашборд и tmux:** `BLOCKED` и «ждёт мерджа» подсвечиваются в
   дашборде и в status-bar tmux; `Ctrl+\` — переключение на окно волны.
10. **Из боевой версии** (`skill-superarmanda/skills/superarmanda/scripts/waves/`) переносятся
    только критичные фиксы: резюме `watch` с диска; привязка журнала к волне по
    `session_id`; кэш смещений журнала; дедупликация событий; `DONE` при мёртвой сессии;
    `redact()` в ленте событий.
11. **Итог цепочки** — `chain-result.md`: PR, мерджи, перезапуски, вопросы, время.
12. **Unit-тесты без tmux:** парсинг журнала, гейт на фикстурах, резюме, `redact()`, fallback.

## Что НЕ делаем

  `review-contract`, manifest superarmanda, классов риска и 7 шагов superarmanda.
- Нет внешних уведомлений (ни ОС, ни мессенджеров).
- superarmanda и `--waves` в `skill-superarmanda` не меняем; в наш флот не раскатываем.
- Нет плагина/marketplace — только репозиторий и `install.sh`.
